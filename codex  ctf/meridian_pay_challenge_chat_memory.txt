6. CONFIRMED / HIGH-CONFIDENCE APK VULNERABILITY #2/#3 CANDIDATE:
EXPORTPROVIDER PATH TRAVERSAL
============================================================

ExportProvider.smali openFile():

It gets:
getFilesDir()

then appends:
"receipts"

It gets:
Uri.getPath()

If path starts with:
"/files/"
it strips that prefix.

Then it constructs:
new File(receiptsDir, p1)

and opens the file.

There is NO canonicalization/path-containment check.

Therefore a URI such as:

content://com.meridian.pay.export/files/../../shared_prefs/session.xml

is a path traversal candidate.

The provider's intended root is effectively:
<data dir>/files/receipts

but a traversal can escape it.

Potential targets:
shared_prefs/session.xml
other app-private files
possibly files outside the app sandbox if sufficient ../ traversal is accepted

The app seeds:
files/receipts/receipt-8827.txt

with:

Meridian Pay receipt
Account MP-0041-8827
Amount: $18.42
Status: settled

The exact source file showed the provider logic and receipt setup.

8. WEBVIEW / DEEP-LINK VULNERABILITY
============================================================

RouterActivity is exported and accepts external intents.

It reads the Intent data and extracts query parameter:
"url"

If missing, it uses:
baseUrl + "/api/v1/promo/public"

Then starts WebViewActivity with extra:
"url"

WebViewActivity:
- creates a WebView
- JavaScript is enabled
- gets the URL
- gets session/base URL
- checks:
  url.startsWith(baseUrl)
- if true, adds:
  Authorization: Bearer <token>
  X-Meridian-Client: MeridianPay-Android/3.2.1 (attested)
- then calls:
  WebView.loadUrl(url, headers)

The important bug:
startsWith(baseUrl) is not a safe origin check.

For example, conceptually:
https://trusted.example
and
https://trusted.example.attacker.example
can share a prefix while being different origins.

The actual challenge exploit still needs to be demonstrated.

There is also a base URL setting in MainActivity:
The user can enter a server field.
The app directly trims the value and calls:
Session.setBaseUrl()
No validation is performed.

Potential consequence:
The WebView may be tricked into loading an attacker-controlled URL while attaching the bearer token and Meridian client header, depending on exact URL construction and runtime behavior.

Again:
DO NOT CLAIM THIS FLAG IS FOUND YET.
It is a strong vulnerability candidate based on the APK.
